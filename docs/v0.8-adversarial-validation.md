# VulnOps V0.8 adversarial validation

## Execution and results

Validation exercised the current working tree, including the adversarial tests, using Python 3.14.2 and pytest 9.1.1 in an isolated temporary environment. No production code or dependencies were changed for this validation. All scanner inputs were local fixtures; intelligence retrieval used controlled responses. No scanner credentials or live network access were required.

Commands executed:

```sh
uv --cache-dir /tmp/vulnops-pytest-cache run --offline --no-project --with pytest python -m pytest tests -q
uv --cache-dir /tmp/vulnops-pytest-cache run --offline --no-project --with pytest python -m pytest tests/adversarial -v -rx --tb=short
```

The offline commands use an already populated temporary pytest cache.

| Scope | PASS | XFAIL | unexpected FAIL | Unexpected PASS |
| --- | ---: | ---: | ---: | ---: |
| Complete suite | 127 | 3 | 0 | 0 |
| Adversarial subset, included above | 30 | 3 | 0 | 0 |

The complete run also reported 339 passing unittest subtests. The classification matrix executes 13,440 combinations within one passing test; these are not additional collected tests.

PASS means the stated current invariant held for the tested scenarios. XFAIL means a stronger desired safety property was intentionally tested and V0.8 failed to satisfy it. All three gap tests use `pytest.mark.xfail(strict=True, raises=AssertionError)`; an unexpected pass would fail the suite. XFAIL is not evidence that the safety gap has been solved.

## Scanner boundary

Source: [test_scanner_boundary.py](../tests/adversarial/test_scanner_boundary.py).

| Scenario / test | Result | Invariant proven |
| --- | --- | --- |
| `test_vendor_fields_do_not_leak_into_internal_finding` | PASS | Vendor IDs, software fields, and scanner-supplied organizational or priority fields are excluded. The join produces exactly `asset_id`, `cve`, `severity`, `asset_criticality`, `internet_exposed`, and `owner_team`; configured local context takes precedence over injected scanner fields. |
| `test_exact_duplicates_collapse_deterministically_preserving_first_occurrence_order` | PASS | Identical machine/CVE observations collapse, repeated normalization is deterministic, first-occurrence order is preserved, and distinct machine/CVE pairs remain distinct. Raw inputs are unchanged. |
| `test_conflicting_duplicates_fail_in_both_orders_after_identity_normalization` | PASS | Conflicting severity fails in either input order, including after whitespace and CVE-case normalization; neither first-record nor highest-severity selection is invented. |
| `test_missing_asset_context_fails_instead_of_returning_partial_findings_or_defaults` | PASS | An unconfigured machine raises a clear error even after a valid observation; no partial result or default context is returned. |
| `test_duplicate_or_ambiguous_asset_mappings_fail_even_when_identical_or_whitespace_padded` | PASS | Identical mappings, one machine mapped to different assets, and different machines mapped to one asset fail. Whitespace does not conceal duplicate identities. |

Scanner names `machineId` and `cveId` disappear during normalization. `scanner_machine_id` is used only through the context join and is absent from downstream findings. Existing regression tests additionally verify that lifecycle and verification continue using `(asset_id, cve)`.

## Classification

Source: [test_policy_invariants.py](../tests/adversarial/test_policy_invariants.py).

| Scenario / test | Result | Invariant proven |
| --- | --- | --- |
| `test_classification_is_invariant_across_non_policy_signals` | PASS | Across 13,440 combinations, only KEV membership and asset criticality determine priority and the exact reason. Severity, EPSS score/percentile, exposure, and ownership do not change classification or mutate inputs. |
| `test_classifier_does_not_read_non_policy_signals` | PASS | Inspection of the current classifier confirms its finding-field reads are restricted to `cve` and `asset_criticality`, with no reads of severity, EPSS, exposure, or ownership. |

The matrix covers all eight KEV/criticality combinations, all four supported severities, all three exposure values, five owner values including `unknown`, seven EPSS scores including `None`, zero, and one, and four percentiles. This is finite value coverage, supplemented by the implementation-read guard; it is not enumeration of every possible probability or team identifier.

The preserved rules are:

```text
KEV + critical asset → P0
KEV                  → P1
otherwise            → P2
```

## Pipeline rejection of malformed input

Source: [test_pipeline_safety.py](../tests/adversarial/test_pipeline_safety.py). All 18 parameterized cases enter through `main()` with real JSON and CSV loading.

For every PASS in this section, the common invariant is explicit failure with exit status 1 and an explanatory stderr message, before KEV/EPSS retrieval, classification, or queue writing. The existing P0 queue and all input files remain unchanged. No organizational default or partial output is invented.

| Scenario / test parameter | Result | Specific invariant proven |
| --- | --- | --- |
| Unknown scanner machine after a valid observation | PASS | Missing context fails the entire run rather than returning the valid prefix or inventing context. |
| Conflicting duplicate: `critical-first` | PASS | Low severity cannot silently override critical severity. |
| Conflicting duplicate: `low-first` | PASS | Critical severity cannot silently override low severity. |
| Ambiguous context: `identical-row` | PASS | Even repeated identical mappings are rejected. |
| Ambiguous context: `one-machine-two-assets` | PASS | One scanner identity cannot resolve to two local assets. |
| Ambiguous context: `padded-machine` | PASS | Whitespace cannot bypass scanner-ID uniqueness. |
| Ambiguous context: `two-machines-one-asset` | PASS | Two scanner identities cannot share one local asset identity. |
| Ambiguous context: `padded-asset` | PASS | Whitespace cannot bypass asset-ID uniqueness. |
| Missing asset ID: `blank` | PASS | Empty asset identity fails rather than being inferred. |
| Missing asset ID: `whitespace` | PASS | Whitespace-only asset identity fails. |
| Missing asset ID: `missing-column` | PASS | Absent asset-ID schema fails before processing findings. |
| Invalid criticality: `unknown` | PASS | Unknown criticality is not silently interpreted as low. |
| Invalid criticality: `urgent` | PASS | Unsupported criticality is not mapped to a policy class. |
| Invalid criticality: `5` | PASS | A numeric-looking string is not treated as a criticality value. |
| Invalid exposure: `yes` | PASS | A truth-like synonym is rejected instead of converted. |
| Invalid exposure: `maybe` | PASS | Unsupported uncertainty is not replaced with `unknown`. |
| Invalid exposure: `True` | PASS | The lowercase exposure contract is enforced. |
| Invalid exposure: `FALSE` | PASS | Uppercase false is rejected rather than silently normalized. |

## Reproduced known gaps

Source: [test_known_v08_gaps.py](../tests/adversarial/test_known_v08_gaps.py). These are stronger desired safety properties, not additional V0.8 states or implemented capabilities.

| Scenario / test | Result | Observed V0.8 behaviour | Missing concept |
| --- | --- | --- | --- |
| `test_unqualified_absence_evidence_cannot_establish_passed_verification` | XFAIL | A resolved finding with bare `vulnerability_present=false` derives `passed`, despite the test requiring `unverified` when evidence is unqualified. | Verification evidence qualification: scan-run success, observation time/freshness, asset coverage, and provenance are not represented. |
| `test_missing_scanner_observation_does_not_remove_previously_open_work` | XFAIL | Previously open work disappears from the active queue when the next scanner file has no observations. The recorded claim remains open; V0.8 does not explicitly mark it passed or resolved. | Observation completeness and coverage semantics, plus retention/reconciliation of previously observed work, are absent. V0.8 cannot distinguish successful absence from failed, incomplete, or non-covering observation. |
| `test_previously_passed_finding_becomes_active_when_observed_again` | XFAIL | After an earlier pass and an intervening empty observation, the reappearing finding remains excluded because the old resolved claim and false verification evidence still derive passed. | Cross-scan reconciliation/regression and the temporal relationship between verification evidence and later observations are not represented. |

There were no unexpected failures or unexpected passes. No production changes were made to satisfy these stronger properties.

## Conclusion

The V0.8 architectural invariants survived the exercised adversarial validation, and the known verification-evidence limitation was reproduced through all three strict XFAIL scenarios.
